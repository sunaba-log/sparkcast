# SparkCast：AIの利用と非機能要件

レビュー用暫定版／2026-10-06（第2版）。第3回の4項目に対応。既存機能を対象とし、開発中のJev等は含めない。対象コードは `5ddf6d6cacbca4f5d8a026ad9c6e97a831090d53`、修正は作業ブランチ上のみ（本番未反映・未マージ）。実環境（dev/本番）の設定・データには接続できておらず未確認。

SparkCastは音声から議事録、紹介文、SNS文を生成し、Podcast運営を支援する。自動化を維持しながら、情報の扱いと公開条件を説明・検証できることを目指す。以下は認証取得や安全性保証を示す資料ではなく、確認範囲を示す記録である。

| 非機能要件 | 確認の方法 | 現在の状態 |
| --- | --- | --- |
| 生成文で原資料の数値・否定・条件を変えない | 合成議事録→紹介文→SNS文を元資料と照合 | 実モデルで3ケース×5試行。数値・否定・条件の反転は0件。**元資料にない情報の付加**（目次の時刻4/15件、作り話の「30万円の誤解」、話者の立場の捏造）と、SNSへの伝播を確認。自動判定では検出できず、人が確認した。対策は未実装 |
| Podcastの取得範囲を通常・代替経路で維持する | 2利用者・2Podcastで、取得・索引・補足・代替経路・最終モデル入力を観測 | ローカルPostgreSQL＋Firestoreエミュレータで確認。検索例外時も他番組のデータなし。dev/本番のDBは未検証 |
| 許可のないPodcastを選択対象にしない | 所有権SQL、他人の指定、権限剥奪 | 実SQLで確認。剥奪後も本人の会話履歴は残る（方針判断待ち） |
| 参照文の命令で回答を誘導されにくくする | 通常・直接攻撃・間接攻撃を、誘導・開示・認可・有用性に分けて判定 | 実モデルで評価。対策前（3試行）は、議事録に埋め込んだ指示に3/3回従い、システム指示の開示要求に2/3回応じた。参照データを区切る対策（2試行）ではいずれも0回で、正答も維持。**対策は試行が少なく、未採用** |
| 自動投稿を意図した公開先・条件に限定する | RSS/Xの公開先、変更・取消、同時実行、失敗時の記録 | 他番組の公開・投稿が既定番組へ流れる問題、二重送信、削除後の送信、任意の投稿予約作成を再現し、修正した。事前承認なしの自動投稿は維持 |
| 処理を追跡し、本文の不要保存を減らす | 処理ID、モデル/プロンプト、公開段階を関連付ける | 評価ハーネスはモデル・プロンプトのハッシュ・利用量を記録する。製品の追跡と本文ログの最小化は未実装 |
| 同時実行・追加呼出しによる利用量を管理する | 回数、入出力量、再試行・停止条件を確認 | 回数の競合を実PostgreSQLで再現（同時10件中最大10件許可）し、原子的な予約へ修正（5試行すべてで1件）。トークン量の上限はない |
| 侵害・不具合時の影響を限定する | 処理別のAPI/Secret棚卸しとIAM照合 | Terraformを確認。Secretの一部が平文の環境変数で設定されている。実権限は未確認 |

## AI Security / Governance Statement（暫定）

AIを議事録・紹介文・SNS案・チャット回答等の生成に利用する。SNS文には生成済み紹介文を再利用するため、元の誤りが後続に引き継がれる可能性がある。生成物を逐語記録や検証済み事実として扱わない。

チャットは選択Podcastの議事録に加え、議題案や未投稿SNS案を参照する。検索失敗時には、同じPodcastの全ナレッジを参照する代替経路がある（他のPodcastへは広がらないことをローカル環境で確認）。会話履歴は利用者単位で保存されるため、Podcast切替や権限変更後の扱いには追加確認が必要である。

Xは事前承認を必須としない自動投稿を継続する方針である。検証では、公開先の境界（他のチャンネルの音声やSNS文が既定番組のRSSやXアカウントから公開される経路）と、取消・同時実行時の二重送信を修正対象とした。修正は本番未反映である。音声/RSSは、処理が途中で失敗しても公開済みのまま残る。配信済みのRSSや投稿済みのXは回収できない。

生成本文がログやDiscordへ複製される経路がある。保存期間・閲覧者・削除方法は確認待ち。元データの編集・削除が、索引・履歴・通知・配信済みコピーへすべて反映されるとは保証しない。

コード、モック、ローカルのDB/エミュレータによる検証と、実モデルによる少数回の評価を実施した。生成では元資料にない情報の付加を、チャットでは参照文に埋め込んだ指示への追従を確認した。発生割合の精度、本番の権限、実費用は未評価である。実装・運用責任者が残課題の対応優先度と受容条件を確認してから、第三者への説明を確定する。

## 公開前の確認事項

- 実モデル評価ができない場合は未実施のまま明示する。
- 公開・停止・編集・削除について利用者が実際に行える操作を確認する。
- 対象コードとデプロイ設定、ログ保存・通知先、運用責任者を照合する。
- 新機能は本編の完成条件にせず、仕様と検証が揃った場合のみ追記する。
