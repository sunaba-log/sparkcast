## 環境上の注意点

現行 `.github/workflows/pr-preview.yml` は、develop向けUI変更のPR作成・更新時に、共有dev DBへのマイグレーションとプレビュー配信を行う。Draft PRでも除外する条件はない。ブランチを分けるだけではDB・Firestore・外部投稿先は分離されない。

初回PRはdocs/evaluationsのみで、このプレビューのパス条件に入らない。UI実装のPRを開く前に、共有devで実行可能な変更か確認し、必要なら独立環境またはプレビュー抑制をチーム運用に合わせて用意する。承認状態の移行は投稿ワーカーとの互換性をそろえた順序で行う。

## 運用方針（2026-10-06レビュー反映）

1. 公開前レビューが有効なら、監査API失敗・不完全応答・監査用文字起こし欠落を「問題なし」と扱わず公開を停止する。レビュー無効の場合の既存運用とは区別する。
2. 自分たちのX投稿は事前確認なしの自動投稿を継続する。確認機能は任意の将来機能とし、実装の必須条件から外す。自動投稿でも意図した配信先、停止条件、失敗時の再試行は確認する。確認必須モードを将来追加した場合は、そのモード内で承認版・宛先・予定時刻を保証する。
3. RAGの未公開情報利用は用途に応じて明示する。配信済み限定と管理者の運営相談の比較結果から採用方針を決める。

実施できないものは阻害要因と残る影響を記録してTODOへ送る。実装のレビュー時には、失われる利便性・再開方法・移行方法を一緒に提示する。X自動投稿では、人による内容確認を追加しないため誤生成が外部へ出るリスクが残る。監査機能がSNS文そのものの正確性を保証するとは扱わない。
