## マージ前に解消・合意したい残件

1. **予定日時の再確認漏れ（再現済み）**  
   一覧取得後に投稿を翌日へ延期しても、確保処理はpendingだけを確認し、そのまま送信する。確保するトランザクション内で最新の予定日時を確認し、延期時に送信しないテストを追加したい。
2. **取消・編集できる期限**  
   削除の検証は「一覧取得後・確保前」に限る。確保後の本文編集・削除は許可される。確保時点を取消期限とするなら、API/UIでもその制約を反映する。現状を「削除後の送信をすべて防止」と説明しない。
3. **一部送信・結果不明時の扱い**  
   スレッド途中失敗や通信エラーでは、一部公開済みでもfailedになり得る。手動再送前の確認、posting滞留時の復旧方法を決める。自動復旧・完全な二重送信防止まで実装済みとは扱わない。
4. **developとの統合と配備**  
   Claude確認時のdevelopではentrypoints/main.pyが競合した。現在の差分で再確認する。UIのPRは共有devへの配備やDBマイグレーションを伴い得るため、CI/CD定義を確認してからPR・統合を進める。

F1〜F4は分割コミット。採用する修正を個別に判断できるが、F2とF3は投稿状態の運用を一緒に確認する。
