# 非機能要件と受入条件（案）

対象：第4回で扱うAI・公開経路。SparkCast全体の性能・可用性・災害復旧要件を網羅するものではない。S1=出力誘導、S2=誤生成と公開、S3=想定外の再利用、S4=処理量増大。

「コードあり」は動作確認済みを意味しない。「観測」は合成データ・モックによる限定的な確認。全行の達成を宣言する資料ではない。

| ID | 利用者にとっての要件 | 受入条件・証拠 | 対応 | 現状 |
| --- | --- | --- | --- | --- |
| PUB-01 | 選択したX投稿の運用条件が守られる | 現運用は事前確認なしの自動投稿。配信先・時刻・停止条件・結果不明時の扱いを確認する。将来の確認必須モードでは未承認/編集後/取消は送信0件、承認版を固定 | S2 | 自動投稿継続の方針を確認。確認機能は将来TODO。自動投稿の境界検証は一部のみ |
| PUB-02 | レビューが未完了なら音声・RSSの公開が止まる | レビュー有効時のAPI失敗、不完全応答、監査用セグメント欠落、承認待ちで公開書込0件。取消・再開時の状態も確認 | S2 | 公開停止の実装・モック回帰テスト完了。低スコア成功/レビュー無効の自動公開も確認。実環境・再開/取消は未検証 |
| PUB-03 | 意図したPodcast・アカウントへ公開される | R2配置先とPodcastを照合。X資格情報が不明・無効なら送信0件 | S2/基盤 | X資格情報欠落時の既定クライアント送信を観測。R2対応は未検証 |
| DATA-01 | 他Podcastの情報がAI入力へ入らない | 異なる利用者・Podcastで、API認可、検索、補足、代替経路、履歴を検証。取得結果と最終モデル入力で確認 | S1/S3 | 既存制御あり。経路横断の受入テストは未実施 |
| DATA-02 | 何がAIで処理・再利用されるか分かる | 参照方針を全取得経路に適用。旧索引・履歴、ログ、通知、訂正・削除の範囲を説明 | S3 | 未公開SNS案を参照するコードを確認。方針・検証未完 |
| AI-01 | 悪意ある指示への挙動と限界が分かる | 同じ条件で変更前後を反復評価。攻撃の到達、指示追従、不要出力、根拠のない断定を別々に集計 | S1 | 評価ケース作成済み。実モデル未実施 |
| AI-02 | 誤生成と訂正による意味の変化を確認できる | 3音声×2回。原音声・認識結果・議事録・紹介文・SNS文を照合。新しい訂正台詞・編集音声も確認 | S2 | 既存のモック処理テストあり。実音声評価未実施 |
| AI-03 | 対策後も通常利用が成立する | 回答可能・情報不足・アイデア相談・運営相談を別評価。不必要な拒否、参照制限による機能低下を記録 | S1/S3 | 未実施 |
| OPS-01 | 処理量を把握して止められる | 長入力・代替経路・再試行・同時実行を確認。入出力量、呼出し数、時間と予算を記録 | S4 | 既存の制限あり。対象経路全体の確認未完 |
| OPS-02 | 生成・確認・公開の経緯を追跡できる | 処理ID、モデル・プロンプト版、参照元、承認版、公開状態を結び付ける。本文の不要保存を削減 | 全シナリオ | ログ等のコードあり。追跡性・保存方針未検証 |
| OPS-03 | 基盤の権限と影響範囲を説明できる | 必要API・データ・Secretを役割別に棚卸しし、実環境との差分・分離計画を記録 | 基盤 | 未実施 |

AI-01〜03は小規模な事例評価とする。実測前に合格率を捏造せず、ケースごとの期待結果を先に固定する。重大な失敗を平均値で隠さない。失敗が残る場合は利用条件・公開条件を見直し、受け入れる範囲を記録する。

審査員向けの説明は「要件 → 実装画面/制御 → 検証結果 → 限界」を各観点1行で示す。この表の現状列を実績で更新して使用する。Xの全件事前確認を実施しているとは説明しない。
