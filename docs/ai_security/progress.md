# 実装・評価の経過

## 2026-10-06：監査不能時の公開停止

### 運用方針

高島のレビューで、Xは事前確認なしの自動投稿を継続する方針を確認した。Xの確認機能は任意の将来機能とし、第4回の必須成果物から外す。自動投稿でも、配信先・予定時刻・停止条件・再試行・訂正方法は確認対象とする。人間による事前確認を行わないため、生成文の誤りが外部へ出るリスクが残る。

実施条件が揃わない項目は未実施の理由と影響を記録し、後続TODOにする。実施済みに数えない。

### 実装したこと

- JevのAPI例外・タイムアウト例外・必須回答欠落・不正な値を低スコアへ置き換えず、`ReviewIncompleteError` として公開を停止する。
- 有限の数値と範囲、既知のカテゴリを検証する。SDKの小数スコアを既存どおり整数へ丸める判定方針は維持する。
- レビュー有効時に監査用セグメントがない、評価が一部欠落/重複/別発話に対応する場合も停止する。
- 要訂正なのに訂正生成が無効、訂正文が空、保存先がない/保存に失敗した場合も公開へ進まない。
- 既存の `failed` 状態に理由を保存してジョブを失敗終了させる。スキーマ・承認UIの変更はない。
- チャンク監査のAPI失敗について、上流のエラー本文をログ・通知へ転記しない。

正常な低スコアの監査結果では従来どおり自動公開する。明示的に `JEV_ENABLED=false` とした運用も維持する。訂正提案を保存した場合の承認待ちは既存機能を使用する。X投稿コードは変更していない。

### 復旧と残る制約

- デプロイ前に `JEV_ENABLED`（既定true）、Jev認証、Speech-to-Text、訂正生成、Firestore保存先が意図した構成か確認する。従来は監査失敗を見逃して公開していた環境では、本修正により処理が停止する。
- 失敗理由の設定/接続を直し、公開未開始・別ジョブによる公開なしを確認して元入力のジョブを再実行する。再開専用UIは未実装。繰り返し実行時の通知・費用、同一エピソードの排他制御は後続確認。
- 監査前の議事録・概要のDiscord通知やログは残る。今回の「停止」は音声/RSS公開とその後のSNS生成を対象とし、外部への情報送信をすべて止めるものではない。
- SDKからタイムアウト例外が返った際の停止は検証した。独自の処理全体の時間上限や再試行の制限を追加したものではない。
- モデルの誤判定・Prompt Injection・誤生成そのものは未評価。Jevで訂正不要となっても正確性は保証されない。
- Xの既定アカウントへの切替は未修正。自動投稿継続と、配信先不明時の切替を許可するかは別の判断であり、後続TODOとする。
- 本番/共有devへの適用、PR #182の承認UIとの結合、認可境界、実音声・実モデル評価は未実施。

### 第4回へ反映する内容

記事の中心を「承認を増やした」から「運用方針に応じて、機械処理が続行してよい条件を定義・検証した」へ更新する。Xの全件確認は導入せず、レビューが有効な音声処理で監査不能を正常扱いしない制御を、実装済みの事例として説明できる。

ただし、記事全体の実装・評価が完了したとは扱わない。実モデル評価などをスキップして公開する場合は、記事の対象を今回の公開条件とプログラムの検証に明示的に限定し、モデルの安全性が改善したという結論は書かない。
