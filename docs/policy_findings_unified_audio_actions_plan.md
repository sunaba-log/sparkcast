# 指摘統合・正確な音声編集・代替音声の実装計画

## 目的と前提

PII と Jev の指摘を根拠付きでまとめ、対象発話に対して「カット」「無音化」「代替音声による置換」を提案する。利用者は PolicyFindingsPanel の各項目で範囲・アクション・代替音声を確認して承認できる。

自律化の範囲は、指摘の統合、範囲推定、推奨アクションと台詞の生成までとする。音声への適用は承認後に行う。Jev はまず本パネルに表示される機密情報・第三者リスク監査を対象にする。既存のファクトチェック訂正介入は編集時の競合検証に含めるが、保存形式の統合は別段階とする。

## 設計方針

### 1. 監査単位と編集単位を分離する

監査は前後文脈を含むチャンクで継続し、編集はその中の単語・句・文の範囲に対して行う。同じ chunk_id であることだけを理由に、全発話を一括編集しない。

TranscriptWord を追加し、word_id、本文、文字範囲、原音声上の start_ms / end_ms、話者、対応精度を保存する。句読点付き本文と STT 単語列の照合結果を保持し、NFKC・空白整理・チャンク結合後も元の文字位置を追跡できる対応表を作る。Python と JavaScript の文字インデックス差を避けるため、API の範囲参照は word_id を基本とする。

`voiced_audio.py` の無音除去後の時間復元も単語単位へ拡張する。削除された無音境界をまたぐ語・発話は境界を考慮し、不確実な範囲として扱う。話者の割当・トラック統合・Firestore 保存まで単語情報を保持する。

STT の時刻は推定値であり、音素境界の正確性までは保証しない。UI で範囲を試聴・微調整できるようにし、精度不足の箇所には局所的な再認識または forced alignment を検討する。文字数比例で得た時刻を正確な時刻として扱わない。

### 2. 検知の根拠と統合された編集案を分けて保存する

元の PolicyFinding は保持し、別の PolicyEditProposal を導入する。

| モデル | 主な項目 |
|---|---|
| PolicyFinding | finding_id、検知元、カテゴリ、chunk_id、根拠文字列、word_ids、確率・閾値、ポリシーバージョン、原音声・文字起こしリビジョン |
| PolicyEditProposal | proposal_id、finding_ids、対象 word_ids、検知範囲、編集範囲、範囲精度、推奨アクション、理由、代替台詞、利用者が選択したアクション、承認状態、version |
| ReplacementAudioAsset | asset_id、生成／録音の種別、台詞リビジョン、保存先、実測尺、形式、ハッシュ、処理状態 |
| AudioEditPlan | plan_id、原音声リビジョン、proposal の確定版一覧、競合解決済み操作、ジョブ状態、冪等キー |

保存先はエピソード配下の `policy_edit_proposals` と `replacement_audio_assets` を追加する案とする。検知結果の確率は検知元ごとに保持し、単純な平均や合算を行わない。

統合ルール:

1. 同一リビジョン・同一対象範囲・同一ルールの重複は表示上まとめ、元の根拠は全件保持する。
2. 同じ対象句について PII と Jev が指摘した場合は、両方を満たす一つの編集案を作る。
3. 同一チャンク内でも離れた対象は別編集案にする。例: 電話番号と別文の第三者批判。
4. 部分的に重なる対象は、一つの操作で解消できるかを判断する。広範囲の Jev 指摘に含まれる PII は、その Jev 指摘の妥当な対象範囲内で統合する。
5. 根拠が局所化できない Jev 指摘はチャンク全体の暫定範囲として表示し、範囲確認を要求する。
6. 利用者の範囲変更で競合が生じた場合は再検証する。カット等の優先順位で黙って上書きしない。

### 3. Jev 判定後に根拠局所化と提案生成を行う

既存の型付き確率判定を維持し、閾値を超えたチャンクに対して、構造化出力による根拠局所化・編集案生成を追加する。現在の Jev インターフェースで必要な出力を扱えるか確認し、難しければ既存の生成モデル基盤を利用する。

入力は前後文脈、word_id 付き発話、全 finding。出力は対象 word_ids、推奨アクション、理由、代替台詞、解消する finding_ids。モデルに編集時刻を直接生成させず、サーバーで word_id から時刻を導出する。出力の参照範囲・引用一致・全指摘の対応を検証する。

推奨の基本方針:

| アクション | 選ぶ条件 |
|---|---|
| 無音化 | PII など局所的な箇所の除去で目的を満たし、尺を維持したい場合 |
| カット | 対象句・文を除いても前後の意味がつながり、不要な空白を残さない場合 |
| 代替音声 | 内容を残す必要があり、安全な言い換えで全指摘を解消できる場合 |

代替台詞を PII・ポリシー検査へ戻して再検証する。利用者が台詞を書き換えた場合も同様。生成失敗・局所化失敗は、原検知を残した要確認状態にし、未完成の案を承認可能にしない。

### 4. カード内で判断と音声確認を完結させる

PolicyFindingsPanel は finding 一覧から proposal 一覧へ移行する。カードを責務別に分割し、一覧の取得・確定処理と、カード内の編集状態を分ける。

各カードに以下を配置する。

- 編集範囲、PII／Jev 等の複数ラベル、統合された根拠、原文中の対象ハイライト。
- 推奨アクションと理由、および三つのアクションの選択。
- 開始・終了の調整、対象区間のみの再生、前後文脈を含む再生。
- 置換時の編集可能な台詞と「合成音声」「ブラウザ録音」の選択。
- 音声生成または録音・停止・取り直し、代替音声の単体試聴、前後を接続した編集プレビュー。
- 承認・却下、保存済み／未保存、生成中／録音中／処理中／失敗の表示。

原音声の範囲再生は onSeek(seconds) だけでは不足するため、範囲再生のコールバックを追加する。原音声・代替音声・プレビューの同時再生を防ぐ。

承認はアクション・範囲・台詞・音声アセットの確定版に紐付ける。変更時には承認を解除する。未保存の判断、未完了アセット、古いプレビューを残したまま編集開始できないようにする。

### 5. 合成音声と録音を共通アセットとして扱う

合成音声は既存のディレクター音声生成経路を調査して再利用する。台詞・音声設定のハッシュで生成を再利用し、生成結果をアセット化する。ブラウザの読み上げ API は配信用音声の生成には使わない。

録音は `apps/ui/src/lib/recording/recorder.ts` の方式を再利用できるか確認し、短尺の録音フックを作る。録音開始時にマイクを取得し、停止・キャンセル・アンマウント時にトラックを解放する。対応 MIME の判定と WAV フォールバック、権限拒否、空音声、アップロード失敗を扱う。

サーバーで形式・長さ・所有権・デコード可否を検証し、共通 PCM 形式へ正規化する。録音内容は再文字起こししてポリシー検査する。録音では台詞の一致だけでなく、実際に発声された内容を確認する。カードには実測尺と検証結果を表示する。

### 6. 原音声基準の編集計画を一度だけ適用する

操作は `[start_ms, end_ms)` の半開区間で扱い、全て原音声リビジョンの座標へ固定する。サーバー側で重複・範囲外・空区間・アセット未準備を拒否してから AudioEditPlan を確定する。

- 無音化: 原区間の長さを維持する。
- カット: 原区間を除去し、前後を接続する。
- 置換: 原区間を除去し、代替音声を挿入する。初期仕様は代替音声の実測尺を採用し、後続を移動する。尺の自動切り詰めや過度な伸縮は行わない。

デコード後の PCM を原座標で分割・結合し、最終的に一度エンコードする。接続部に短いフェードを適用し、クロスフェードを使う場合も削除対象の原音声が漏れないようにする。フェードが元の対象範囲外を大きく侵食しないよう制限する。

原音声→編集音声の時間対応表を出力し、カット後の再生位置、置換区間、既存訂正音声の挿入位置、字幕・チャプター等の時刻参照へ反映する。削除区間内の位置は削除済みとして扱う。話者別トラックがある場合も、初期仕様は最終ミックス全体の区間編集とし、重なって話す別話者への影響を表示する。

プレビューと本編集は同じ編集エンジンと確定版パラメータを使用する。原本は保持し、新しいレンディションを作る。

## API・保存・ジョブの変更

- 既存 policy-findings GET は根拠の取得用として維持し、proposal の取得・保存 API を追加する。
- proposal 更新に version による競合検出を導入する。範囲、アクション、台詞、asset_id をサーバー検証する。
- 代替音声の生成、録音アップロード／確定、状態取得、署名付き試聴 URL の API を追加する。
- proposal の確定版から編集プレビューを生成する API を追加する。
- review-policy-findings と apply-interventions を proposal／AudioEditPlan ベースへ移行する。クライアントから任意の音声 URL を編集入力にしない。
- 全必須 finding が承認済み案でカバーされるか、明示的に却下されているかを検証する。旧 finding.status は必要なら互換用に派生させる。
- 既存 director_interventions とも編集の競合を検証し、両方の未判断状態を考慮して公開状態を決定する。
- 状態の条件付き更新とジョブの冪等キーを導入する。送信前に編集要求を確保し、ジョブ送信失敗・再試行時の復旧を定義する。Firestore と SQL のまたがる更新は確定 plan と再試行可能なジョブ要求を基準に整合させる。

## 実装順序と完了条件

| 段階 | 実装内容 | 完了条件 |
|---|---|---|
| 0. 契約・編集サービス確認 | 外部編集サービス、原本保管、TTS 経路を確認。モデル、置換尺、リビジョン、API 契約を固定 | 一件の指摘→案→アセット→編集までのデータ契約が確定 |
| 1. 正確な範囲の基盤 | 単語情報保持、正規化対応表、無音除去の時刻復元、PII スパン保存 | 電話番号等がチャンク全体ではなく対応単語の範囲になり、保存後も再現できる |
| 2. 統合と自律提案 | Jev 根拠局所化、proposal 保存、重複統合、推奨理由・台詞・再検査 | 同一対象の PII＋Jev は一案、離れた指摘は別案。未解決の根拠が消えない |
| 3. カット・無音化を縦につなぐ | カード、範囲再生・調整、保存・承認、編集 plan、二種の編集 | UI で確認した原区間に一度だけ適用され、後続位置が正しく対応する |
| 4. 合成音声置換 | TTS アセット、カード内試聴、文脈プレビュー、置換処理 | 原発話を除去し、検査済みの選択音声を挿入できる |
| 5. ブラウザ録音置換 | 録音・再録音、アップロード、正規化、再認識・監査 | 録音から試聴・承認・置換まで一項目内で完結する |
| 6. 移行・運用 | 旧 finding 読み取り、状態遷移回帰、失敗復旧、監視 | 既存エピソード・訂正介入・原音声公開確認を壊さず段階導入できる |

旧 finding は局所スパンを持たないため、チャンク範囲の要確認案として読み取る。正確な範囲が必要な場合は原音声から再認識し、既存の承認を自動的に新案へ引き継がない。機能フラグで段階導入する。

## 検証計画

| 領域 | 重要なケース |
|---|---|
| 範囲対応 | 日本語、英数字、NFKC、句読点、同じ語の繰り返し、複数文、チャンク結合、単語時刻欠落、無音除去境界 |
| 指摘統合 | 完全重複、包含、部分重複、同一チャンク内の離れた指摘、話者重複、局所化失敗 |
| 提案品質 | PII＋Jev の両方を解消する台詞、残存 PII、根拠のない事実追加、不正 word_id、生成失敗 |
| 音声編集 | 区間外の PCM が維持されること、無音化の尺、カット・置換の尺、先頭・末尾、複数編集、対象原音声の漏れ、時間対応表 |
| アセット | TTS・録音の準備未完了、台詞変更後の古い音声、録音に含まれる新たなリスク、異なる利用者・エピソードの asset_id |
| UI・API | 保存前の編集開始、変更後の承認解除、範囲再生停止、録音権限拒否、再試行、二重クリック、version 競合 |
| 公開フロー | 未判断での編集・公開拒否、全件却下後の公開確認、原本保持、既存訂正介入との競合、ジョブ失敗・再送 |

合成信号で機械的な区間・尺の正しさを検証し、日本語の実音声で語頭・語尾の欠けや情報の取り残しを評価する。音声の機械的編集精度と、STT による範囲推定の精度は分けて評価する。

## 実装開始時に残る選択事項

この計画では、置換は自然な実測尺、自律提案後の人手承認、最終ミックス全体の編集を初期仕様とする。TTS の声は既存設定を第一候補にする。固定尺置換、話者別の編集、既存ファクトチェックのカード統合は、その必要性と既存サービスの対応を確認して拡張する。

## 実装反映（2026-10-11）

- 単語時刻・文字範囲・監査チャンクの構成セグメント／単語IDを保存する。無音除去の境界をまたぐ単語は精密範囲に使用しない。
- 編集案は `policy_reviews/current` にversion付きで保存する。元findingと全単語列はこのドキュメントへ複製せず、読み取り時に結合する。
- 新規監査結果では自動提案を起動する。失敗時は暫定無音化案を保持し、手動の範囲確認または提案の再生成を行う。
- カット・無音化・置換、範囲確認、合成／録音の準備・カード内試聴、文脈プレビュー、確定済み編集計画の配信処理を接続した。
- 既存ファクトチェックの判断を個別に保存できるようにし、承認済み訂正音声も同じ原音声座標で挿入する。削除・置換内部の挿入は競合として拒否する。
- 公開後の文字起こしと監査マーカーはレンディションの時刻を使用する。監査カードの試聴は原音声を使用する。
- 初期制限は、録音120秒、1回の確定で最大450 finding。STT単語時刻の誤差は試聴と開始・終了の手動調整で補正する。forced alignment、固定尺置換、話者別編集は追加拡張とする。
- 外部サービスを呼ばない単体・回帰テストとブラウザのUI確認を実施する。Cloud Run上の実TTS／STT／Jevを使用した通し確認はデプロイ環境で行う。
