## 作業手順（実行担当者向け・本タスクでは未実行）

### 1. 対象固定・事前検証

```sh
git fetch origin
git switch release/261103
git pull --ff-only origin release/261103
git rev-parse HEAD origin/main
git diff --stat origin/main...HEAD
git merge-tree --write-tree origin/main HEAD
```

main / releaseの変更があれば差分を再確認。PR CIとdevでの動作確認を完了させる。以下の本番変更はメンテナンス枠内で行い、旧UI revision、Jobイメージ、Terraform state、DB / Firestore / RSSの復旧ポイントを記録する。

### 2. RSS既存データの照合と必要時の移行

チャンネルごとに現在配信中のfeed.xmlを退避。公開済みepisode_id、GUID、pubDate、音声URL・サイズ・長さをPostgreSQL / Firestoreと照合する。再構築対象はSQLで `status='completed' AND published_at IS NOT NULL`、Firestoreで `is_published=False` の項目は除外される。

```sh
cd apps/automator/app
uv sync
uv run python scripts/migrate_rss_to_firestore.py \
  --feed-file /secure/backup/feed.xml --podcast-id ACTUAL_PODCAST_ID \
  --project-id sunabalog-prod --dry-run
```

このスクリプトはタイトルの `#数字`、なければフィード順でepisode_idを決める。実DB IDとの一致を全件確認し、不一致があれば移行方法を修正してから進む。既存タイトル・説明・状態も上書きするため、一律再実行しない。必要なチャンネルだけ、両DBのバックアップ後に本番 `DATABASE_URL` を安全に環境注入して同じコマンドから `--dry-run` を外す。認証情報を引数やログへ出さない。スクリプトは両ストアを跨ぐトランザクションではないため、失敗時は部分反映を照合する。

### 3. DB migrationを先行

リポジトリルートへ戻り、認証済みの環境で本番Supabase接続先を確認して実行する。シェルのトレース出力は無効にする。

```sh
(
  cd apps/ui
  npm ci
  export DATABASE_URL="$(gcloud secrets versions access latest --secret=supabase-database-url-prod --project=sunabalog-prod)"
  npm run db:migrate
)
```

追加対象は `011_add_ai_director_states.sql`、`011_add_director_audit_states.sql`、`013_add_audio_audit_policy.sql`、`014_add_audio_audit_policy_enabled.sql`。migration runnerは番号ではなくファイル名で管理するため011の2本とも実行される。schema_migrationsの適用記録、status制約の `awaiting_publish_confirmation`、podcasts.audio_audit_policyを確認。途中失敗時は新コードの適用を止める。013適用済みで片方の011のみ未適用という特殊な履歴では制約が後退し得るため、実行前に履歴を確認する。

### 4. Jev secretを準備しインフラを先行適用

Docker、gcloud ADC、本番権限、ルート `.env` の必要なCloudflare設定を準備する。環境切替時は明示的にbackendを再構成する。

```sh
make terraform-reconfigure ENVIRONMENT=prod
make terraform-base ENVIRONMENT=prod COMMAND="plan -no-color"
```

新secretにversionがない場合、初回だけ本体を作成して値を登録してから全体をapplyする。既存secretがTerraform管理外なら作成せずimport方針を確認する。

```sh
make terraform-base ENVIRONMENT=prod COMMAND="apply -target=google_secret_manager_secret.jev_api_key"
gcloud secrets versions add jev-api-key --project=sunabalog-prod --data-file=/secure/jev-api-key
make terraform-base ENVIRONMENT=prod COMMAND="plan -no-color"
make terraform-base ENVIRONMENT=prod COMMAND="apply"
```

`/secure/jev-api-key` は管理者が安全に用意した実ファイルに置き換える。既に有効なversionがあれば登録は不要。target applyは初回secret準備専用で、全体plan/applyを省略しない。破壊・想定外の置換があれば中止。新Jobはこの時点で更新されるためDB/RSS準備と実行停止を先に完了する。

```sh
gcloud run services describe sparkcast-automator-policy-media-prod --project=sunabalog-prod --region=asia-northeast1 --format='value(status.url)'
gcloud storage buckets describe gs://sparkcast-automator-policy-audio-prod --project=sunabalog-prod
```

policy-mediaのReady、secretアクセス、UIの環境変数 / IAMを確認。releaseブランチを `cd.yml` の `target_branch` に指定しない。現行workflowはmain以外をdevと判定するため、この先行適用はreleaseチェックアウト上で `ENVIRONMENT=prod` を明示する。
