# 収録ルームを、運営者の番組の仲間だけに使わせる

## Context

収録ルーム（#166）は、利用者どうしの音声通話とテキストチャットを Worker と SFU で中継する。誰でも使えるサービスとして提供すると、電気通信事業法の「他人の通信の媒介」に当たり、届出が要る。そのため prod は閉じていた。

一方で、この機能の目的は、運営者が自分の番組を収録することである。総務省「電気通信事業参入マニュアル［追補版］」p.2・p.10 では、自らの事業のために取引先などと行う通信は「自己の需要」に当たり、電気通信事業には当たらないとしている。

## Decision

- 収録ルームを作成・操作できるのは、**admin と、admin が制限を解除した（承認した）ユーザーだけ**にする。prod の登録は事前登録と承認が要るので、承認を「番組の仲間」の指定として使い、別の切り替えは設けない（手作業を増やさない）。
- 招待 URL から入るゲスト（番組の出演者）はアカウントなしのまま参加できる。ルームを作るのは、許可された運営側の人だけである。
- 画面（サイドバー・`/record`）も API（作成・入室・ホスト操作）も、同じ判定で閉じる。画面だけを隠しても、API が開いていれば提供したことになる。
- **お試しの共有アカウント（dev のゲストモード）は使えない。** 誰でも入れるため、使わせると他人の通信の媒介になる。
- この前提で prod を開ける（`enable_recording = true`、リポジトリ変数 `RECORDING_PROD_ENABLED=true`）。

## Consequences

- 他の番組（運営者の番組でないもの）にこの機能を使わせるなら、届出が要る。制限を解除するのは、運営者の番組の仲間に限る。
- 既に作られたルームは、ホストの許可を外しても期限（`RECORDING_ROOM_TTL_HOURS`）まではゲストが入れる。新しいルームは作れず、ホストの操作もできない。
- 録音への同意は入室前に取る。音声の取得と利用目的は、プライバシーポリシーに書き足す（人の作業）。
