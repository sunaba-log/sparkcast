## 詳細

### I-01 全却下→原音声公開の状態を保存できない（A）
- **再現**：`evaluations/hackathon_audit/run-ui.sh` の V1-UI-08。リポジトリの migrations で作った DB で、すべての指摘を却下する。
- **実結果**：`UPDATE episodes SET status='awaiting_publish_confirmation'` が `value too long for type character varying(20)` で失敗する。旧経路は 500、統合経路は 409 を返し、原音声公開（confirm-original-publish）は 409 のまま。
- **影響**：主張「全提案を却下して原音声を公開する」が、migrations どおりの DB では動かない。dev・本番の DB が同じ定義かは未確認（列を手動で変更していれば動く）。
- **推奨修正**：migration を追加する（`ALTER TABLE episodes ALTER COLUMN status TYPE VARCHAR(32)`）。状態遷移を含む API テストを、実 PostgreSQL で回す。
- **暫定回避**：dev・本番の列定義を確認する。未修正の環境では、全却下の公開を手作業で行わない。

### I-02 エピソード番号の重複と公開音声の上書き（A）
- **再現**：`test_episode_numbering.py`（実際の `PostgresEpisodeRepository`）。
- **実結果**：番号は公開時に `SELECT COUNT(*) FROM episodes WHERE podcast_id=…`＋1 で決まる。未公開・処理中・承認待ち・失敗の行も数える。3件アップロード済みの番組では3件とも `#4`・`{prefix}/ep/4/audio.mp3` に書き込み、後の公開が前の公開音声を上書きした。1件ずつでも `#2` から始まる。
- **影響**：承認待ちのエピソードがある間に別の回を公開すると、承認後の公開（原音声公開を含む）で、公開済みの回の音声が置き換わる。RSS の音声URLは同じキーを指すため、聴取者には別の回の音声が届く。編集公開は `renditions/{plan}.mp3` なので上書きしない。また、R2 のキー接頭辞は配備ごとに固定で、番組ごとではない。そのため、番組が複数ある場合は番組をまたいで同じキーになる。
- **推奨修正**：番号を、アップロード時または初回公開時に一度だけ採番して保存する。公開音声キーにエピソードID（または番組ID）を含める。
- **暫定回避**：承認待ちの回を残したまま、次の回を公開しない。

### I-03 再監査APIに状態の前提条件がない（A）
- **再現**：V1-UI-01（API）、V1-02（ワークフロー）。
- **実結果**：`retry-audit` は状態を問わず `auditing` に更新し、監査からジョブを再起動する。再監査で指摘が出なければ、前回の未判断の指摘・訂正介入を空で上書きし、自動公開する。編集中に呼べば、編集ジョブと並行して動く。画面のボタンは failed のときだけ表示されるが、API は制限していない。
- **影響**：Jev の判定は確率的なので、承認待ちの回に再監査すると、人の判断を経ずに公開されうる。
- **推奨修正**：`UPDATE … WHERE status IN ('failed')` の条件付き更新にし、更新できなければ 409 を返す。
- **暫定回避**：承認待ち・編集中の回で再監査APIを呼ばない（UI 以外から呼ばない）。

### I-04 訂正介入だけの回は反映も原音声公開もできない（A）
- **再現**：V1-UI-09、V1-UI-04。
- **実結果**：ポリシー指摘が0件の回では、統合パネル（PolicyFindingsPanel）が表示されない。訂正介入パネルの「カットイン編集を実行」は旧経路を呼び、外部編集サービスの `AUDIO_EDITOR_URL` を要求する。infra に定義がないため 503 になる。全却下しても状態が変わらず、原音声公開へ進めない。
- **影響**：主張「承認した訂正を配信用音声へ反映」が、ファクトチェックの指摘だけの回では成立しない（dev に `AUDIO_EDITOR_URL` が手動設定されていれば別。未確認）。
- **推奨修正**：訂正介入パネルからも統合経路（planVersion）で編集計画を作る。訂正介入がすべて却下され、ポリシー提案が0件なら、公開確認へ進める。
- **暫定回避**：なし（指摘だけの回は手作業で公開する必要がある）。

### I-05 旧判断APIが未判断の訂正介入を無視する（A）
- **再現**：V1-UI-02（I-01 を仮に直した状態で実行）。
- **実結果**：統合レビュー（`policy_reviews/current`）がまだ無い回では、`review-policy-findings` で全指摘を却下できる。このとき訂正介入が未判断でも `awaiting_publish_confirmation` になり、原音声公開のジョブが起動する。
- **影響**：主張「要確認事項が残る場合は公開を停止する」と食い違う。画面は統合レビューを先に作るため、通常の操作では起きにくい。
- **推奨修正**：統合経路と同じ訂正介入の確認を入れるか、旧APIを廃止する。

### I-06 訂正台詞の再検査がない（A）
- **再現**：V2-05、V2-UI-01。
- **実結果**：代替音声の台詞は、合成・録音の時点でローカルPII・機密語・Jev の検査を受ける。一方、訂正介入の台詞（Gemini 生成。利用者が編集できる）は検査されない。機密語を含めて承認すると、編集計画にそのまま入り、編集時に合成・挿入され、編集後の文字起こしと再生成される議事録にも入る。
- **影響**：主張「機密語の除去」を、訂正台詞の経路から崩しうる。AIの訂正文に新しい誤りが入った場合も、自動では止まらない。
- **推奨修正**：訂正介入の保存時（または編集計画の作成時）に `verify_text` と同じ検査を行う。合成済み音声を承認時にアセット化し、ハッシュで固定する。

### I-07 機密語の照合が完全一致のみ（B）
- **実結果**：大文字小文字以外の正規化がなく、全角数字・空白・ひらがな・漢字の表記を検出しない（D02〜D05）。STT が数字を全角で出す、または漢字に変換すると見逃す。Jev のポリシー判定で検出されるかは未確認（実API未実施）。
- **推奨修正**：NFKC 正規化と空白除去を照合の前に行う。表記ゆれの登録を UI で案内する。
- **運用での限定**：機密語に読み・表記ゆれを併せて登録する。

### I-08 ローカルPII検出の範囲（B）
- **実結果**：架空の氏名（「山田花子」「佐藤一郎」）を検出しない。メールは「example.in」だけを URL として検出する。住所は「丸」で途中まで、読み上げた数字は検出しない（D06〜D08、D11、D14）。
- **推奨修正**：GiNZA の人名ラベルを Presidio の PERSON に対応付ける。メールのパターンを追加し、検出範囲を単語境界まで広げる。
- **説明での限定**：「ローカル検出は電話番号・郵便番号・URL・住所の一部の定型パターン」と書く。

### I-09 監査前の Discord 通知（B）
- **実結果**：音声認識の直後に議事録全文を、要約の直後にタイトル・紹介文を送る（V2-01）。
- **推奨修正**：公開完了まで本文を送らない。件数・状態だけを送る。

### I-10 チャットが原文を読む（B）
- **実結果**：編集公開後も `transcripts`（原文）を知識にする。エピソード画面は `rendition_transcripts` を使う（V2-UI-03）。
- **推奨修正**：`active_edit_plan_id` があれば `rendition_transcripts` を読む。原文を使う場合は削除区間を除く。
- **影響の範囲**：チャンネルのメンバー（原文も閲覧できる権限内）に限られる。公開データではない。

### I-11〜I-18
- **I-11**：Gemini の裏取りで「正しい」「概ね正しい」と判定されると記録も残さずに除外するため、AIの誤判定を人が見つけられない。除外した発話と根拠を画面に「AIが正しいと判断」として残すことを推奨する。
- **I-12**：機密語の指摘には文字位置がなく、常にチャンク範囲になる。範囲はレビュー担当者が縮められる（チャンク精度の指摘は制限なし）。範囲の誤差はそのまま残留音になる（V2-13）。STT の単語時刻の精度は実音声で要評価。
- **I-13**：外部公開の許可は、番組単位の監査の有効・無効だけ。エピソードごとの公開許可や予約はない。
- **I-14**：費用・外部送信の説明に影響する。「ローカルで判断できない発話だけを Jev に送る」構成ではない。
- **I-15**：監査トレースは障害解析に有用だが、保存期間・閲覧者を説明する必要がある。
- **I-16**：操作順の依存。画面で順序を案内するか、訂正介入の保存時にも公開確認への遷移を判定する。
- **I-17**：`render_policy_audio` の接合部に短いフェードインを加える。
- **I-18**：承認画面で「根拠なし」を明示する。
